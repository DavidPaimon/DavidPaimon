I build production software for vehicle fleet operations — GPS telemetry, regulatory
compliance, preventive maintenance and internal support tooling. I work the full stack:
the PostgreSQL schema and its migrations, the API on top of it, and the interface the
dispatcher or the mechanic actually uses in the field.

### What I work on

**Fleet management & telematics SaaS** — a multi-tenant platform for transport companies
in Colombia, on a ~700-table PostgreSQL schema with partitioned telemetry and an
S3-backed historical archive. I ship features end to end: GPS ingestion and historical
querying, road-safety compliance workflows (PESV), preventive maintenance and quotation
approval chains, fuel control, vehicle inspections, GPS hardware provisioning with remote
FOTA configuration, and the Excel/PDF operational reporting that field teams run on daily.

**Service desk platform** — ticketing for internal and client-facing support: SLA policies
per company, AI-assisted intake and routing, team performance metrics, per-tenant
visibility rules, and real-time presence over WebSockets.

### How I work

- **I own the whole slice.** A feature is mine from the migration to the rendered
  component — not one side of an API contract.
- **I ship to live systems.** Backwards-compatible migrations, per-tenant data isolation
  and staged rollouts on platforms that run fleets in real time. A bad deploy stops trucks.
- **The hard part is the domain.** Colombian transport regulation, maintenance cost rules
  and SLA arithmetic are where the bugs actually hide — not in the framework.
- **Right language for the job.** Python for the core API, Go for high-volume report
  generation, TypeScript/NestJS for the service desk.
